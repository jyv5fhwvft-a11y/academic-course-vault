🎪 Index Cards02 / 04

The Library Ledger Analogy

The physical text blocks on disk store the literal contents. The **Inode** is the ledger metadata card taped inside the cover.

It stores administrative metrics (Owner, Permissions, Sizing) alongside shelf coordinate indices (Block Pointers). To track oversized files, it notes a coordinate directing straight to a secondary card box filled with deeper block locations (Indirect Pointers).

🔍 Pointer Trees03 / 04

Asymmetric Index Trees

To save data space while remaining scalable, inodes employ multi-tiered pointer arrays:

• Direct Pointers: Array slots addressing physical raw data sectors immediately.

• Single Indirect: Points to an interim sector containing tracking pointer addresses.

• Double Indirect: Branches exponentially to handle vast multi-gigabyte structures.

🛠️ Capacity Math04 / 04

Computing Inode Capacity Limits

Sizing parameters with 12 Direct Pointers, 1 Single Indirect, 1 Double Indirect under a 4KB block and 4-byte pointer footprint:

Direct Blocks: 12 * 4KB = 48 KB Single Indirect: 4096 / 4 = 1024 pointers -> 1024 * 4KB = 4 MB Double Indirect: 1024 * 1024 = 1,048,576 pointers -> 1,048,576 * 4KB = 4 GB Total File Limit = 48 KB + 4 MB + 4 GB = 4.004 GB (Asymmetric trees achieve massive expansion layout bounds with negligible overhead!)
