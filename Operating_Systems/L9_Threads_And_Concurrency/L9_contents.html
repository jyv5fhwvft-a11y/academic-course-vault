Lecture 09: Threads & Concurrency Models

🎯 1. Objective

Contrast the architectural memory boundaries of independent processes against concurrent threads, and delineate Many-to-One, One-to-One, and Many-to-Many scheduling architectures.

🛑 2. Prerequisites

L05, L06.

🎪 3 & 4. Pedagogical Analogies

Analogy 1 (Everyday Life): Stage Actors Sharing a Single Props Table

Imagine a theatrical play. A Process is an entire independent stage production running in its own auditorium building. If you want two separate processes to coordinate, they have to physically mail letters across town (Inter-Process Communication). A Thread is like hiring multiple separate actors (Execution Points) to step onto the same stage inside the same building. They each have their own script folder (Thread Stack) and perform actions independently, but they all share the exact same props table, background scenery, and storage crates (Shared Address Space/Heap). If one actor knocks over the shared props table, every single actor is impacted immediately.

Analogy 2 (Pure Technical): Independent Windows vs. Isolated Tabs within a Web Engine

Multiple processes match running a standalone text editor alongside a standalone video game. Threads match opening multiple tabs inside a modern web browser instance, where every tab shares a pool of background caching memory.

🔗 5. System Cohesion Matrix

Relies On: L05 (Process Anatomy) — Threads reuse the parent process's Data, Text, and Heap boundaries while requiring their own independent Stack frames.

Feeds Into: Module 3 (Memory Management) — Shared memory models mean threads directly point to overlapping virtual page addresses, which serves as the essential core driver for Module 4 Process Synchronization.

🔍 6. Core Breakdown

A thread is the fundamental lightweight unit of CPU utilization. Unlike processes, which maintain absolute isolation, threads belonging to the same process share their Code segment, Data segment, and Operating System resources (like open files). However, every individual thread must possess its own unique Thread ID, Program Counter, register state cache, and isolated Stack frame to track private function execution paths.

In the Many-to-One model, multiple user threads map to a single kernel thread context; thread switching is incredibly fast, but if one user thread blocks on I/O, the entire process freezes. The One-to-One model (used by modern Linux and Windows) maps every individual user thread directly to its own scheduled kernel thread, unlocking true parallel processing across multi-core chips.

🏷️ 7. Lexicon / Terms

  • Thread A lightweight concurrent sequence of instructions executing within the shared ecosystem context of a parent process.
  • User-Level Thread A thread managed completely in user space by an app library without the underlying kernel core being aware of its boundaries.
  • Kernel-Level Thread A thread maintained, tracked, and scheduled natively by the operating system core within Ring 0.
  • Concurrency Enabling multiple execution paths to make progress over overlapping blocks of time (via fast time-slicing or true parallel cores).

🛠️ 8. Practical Example

#include <pthread.h> #include <stdio.h> void* thread_runner_routine(void* arg) { printf("Hello from concurrent Thread ID: %ld! We share the same Heap/Data.\n", pthread_self()); return NULL; } int main() { pthread_t worker_thread_id; printf("Main parent thread spawning lightweight worker...\n"); // Spin up an independent concurrent instruction thread pthread_create(&worker_thread_id, NULL, thread_runner_routine, NULL); // Main thread waits for the concurrent sibling worker to finish its run pthread_join(worker_thread_id, NULL); printf("Worker finished. Main thread exit routine finalized.\n"); return 0; }

🎯 9. Interactive Classroom Activity

The Task Manager Thread Inspection Hunt: Have all students pull up their laptops. Instruct Windows users to open Task Manager and turn on the "Threads" column header view. Instruct Mac/Linux users to open Activity Monitor or run htop.

Have them locate a heavy app instance like a web browser or communication client, note that it uses 1 or 2 core processes, but expand it to reveal the dozens of active concurrent threads running inside that single container space.
