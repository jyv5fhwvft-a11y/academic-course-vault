Lecture 06: Process Execution Mechanics Summary

1. Objective

Explain the exact operational lifecycle difference between cloning an address space (fork) and overriding an address space (exec), and trace register states during a context switch.

2. Prerequisites

L03 (Syscall Interface), L05 (Process Anatomy).

3 & 4. Pedagogical Analogies

Analogy 1 (Everyday Life): Swapping Runners Mid-Relay
Imagine a track-and-field relay race. Executing a fork() system call is like the current runner magically duplicating themselves into a perfect clone runner standing right next to them; both clones have the exact same muscle memory, are running at the exact same speed, and are looking at the exact same spot on the track. Executing an exec() call is like that runner keeping their physical body but instantly handing them an entirely new task script (e.g., throwing a javelin instead of running). A Context Switch is the referee pausing the race, carefully writing down exactly where the current runner stood on the track, making them step aside, and letting the next runner onto the track based on their previously recorded track position ledger.

Analogy 2 (Pure Technical): Git Branching vs. Project Overwriting
A fork() system call is identical to a git branch command—it duplicates the exact state of the commit timeline into an isolated copy. An exec() system call is identical to deleting all code files inside a folder and cloning a completely different repository into that exact same directory path.

6. Core Breakdown

In Unix-like systems, new processes are created via a two-step mechanism. The fork() system call clones the calling process, creating an identical child process. The child receives a unique PID, but copies the parent's file descriptors, environment, and address space. Crucially, fork() returns 0 inside the child process, but returns the child's real PID inside the parent process, allowing code to branch.

The exec() family of calls overrides the current process image, wiping the stack, heap, and data segments to load a brand new executable binary file. A Context Switch occurs when the kernel scheduler shifts the CPU core from executing one process to another, requiring saving the active CPU registers into the outgoing process's PCB and restoring the register values from the incoming process's PCB.

7. Lexicon / Terms

• fork(): A system call that duplicates the current process to create an isolated, matching child process container.
• exec(): A system call that overrides the active process address space with a new executable binary program image.
• Context Switch: The physical hardware/software process of saving the active CPU register state and restoring a different task context.
• PCB Save/Restore: The computational steps during a context switch that copy registers to or from a task's PCB kernel cache.

8. Practical Example

#include <unistd.h> #include <sys/types.h> #include <stdio.h> int main() { pid_t rc = fork(); if (rc < 0) { fprintf(stderr, "Fork failed\n"); } else if (rc == 0) { printf("Child process (PID: %d) launching 'ls' command...\n", getpid()); char *args[] = {"/bin/ls", "-l", NULL}; execv(args[0], args); } else { wait(NULL); printf("Parent process resumed execution line securely.\n"); } return 0; }
