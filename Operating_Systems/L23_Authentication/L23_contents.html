Lecture 23: Authentication

🎯 1. Objective

Compare password-based and biometric authentication models and identify an unalterable systemic vulnerability in each design.

🛑 2. Prerequisites

L22 (Access Control).

🎪 3 & 4. Pedagogical Analogies

Analogy 1 (Everyday Life): The Secret Password, The Safe Key, and The Fingerprint

Proving who you are down at a secure facility relies on three core human vectors: Something you know (a typed combination password), Something you have (a physical brass key or access fob token), or Something you are (your physical fingerprint pattern layout).

Analogy 2 (Pure Technical): SHA-256 One-Way Hashing vs. Heuristic Biometric Vector Sensors

Software credential checks run a string through an arithmetic compression function to match a database key, while biometric scanners translate analog organic geometric structures into static data signatures.

🔗 5. System Cohesion Matrix

Feeds Into: L24 (Program Exploits) — A failure to secure stored authentication keys allows rogue threads to hijack system control streams.

🔍 6. Core Breakdown

Before the kernel can enforce access permissions, it must establish a verified identity through Authentication Factors. Passwords represent "something you know." To prevent local storage theft, modern kernels never save plaintext characters; instead, they run inputs through a one-way mathematical function appended with a random string (Salted Hash).

Biometrics represent "something you are." While passwords can be leaked, they can easily be altered or reset; biometric traits can never be "reset" if compromised, permanently changing the baseline risk calculations of a secure system topology.

🏷️ 7. Lexicon / Terms

  • Authentication Factor An explicit operational category used to verify a user's digital identity boundaries (Knowledge, Possession, Inherence).
  • Multi-Factor Authentication (MFA) Requiring a user to validate two or more distinct authentication categories before granting entry access.
  • Salted Hash Appending a random sequence of characters to a user password before passing it through a cryptographic one-way hashing function to neutralize dictionary lookup attacks.

🛠️ 8. Practical Example: Windows Hello vs. Plaintext Form Validation

Evaluating storage and exposure risks across baseline verification architectures:

------------------------------------------------================= 1. PLAINTEXT / TRADITIONAL FORM STORAGE FRAILTY: When a user authenticates using a raw plaintext password string, a local database breach exposes the target vector to brute-force dictionary attacks if left unhashed and unsalted. 2. WINDOWS HELLO HARDWARE ISOLATION: Windows Hello converts local fingerprint sensor scans into a localized, hardware-locked cryptographic signature key. This prevents raw biometric imagery data from ever leaking into standard storage channels or leaving the trusted platform module (TPM) hardware boundaries. ------------------------------------------------=================

🎯 9. Interactive Classroom Activity

The Banking Login Architecture Challenge: Split the classroom into small groups. Task them with drafting the authentication pipeline flow diagram for a high-security banking utility.

Have them defend their chosen multi-factor constraints and evaluate how their app will handle a scenario where a user's biometric baseline signature is leaked into non-volatile storage pools.
