🎪 Piggy Bank02 / 04

The Shared Piggy Bank Analogy

Two siblings simultaneously add $1 to a digital bank holding $100. Both read the value $100 concurrently, add 1 in their heads, and write back $101 consecutively, missing a whole update line.

This data hazard is a **Race Condition**. To resolve it, we introduce a **Mutex Lock**—a bathroom key token that grants one thread complete modification isolation.

🔍 Critical Sections03 / 04

Enforcing Mutual Exclusion

A **Critical Section** is any window of source instructions that modifies shared mutable state properties.

Enforcing mutual exclusion demands **Atomic Operations** (like Test-and-Set) that check and flip resource lock state variables in a single, indivisible CPU clock line.

🛠️ Mutex Guards04 / 04

Refactoring with POSIX Mutex Locks

Using mutual exclusion guards to establish atomic serial access boundaries over shared global segment resources:

pthread_mutex_t bank_lock = PTHREAD_MUTEX_INITIALIZER; pthread_mutex_lock(&bank_lock); // Entry Path: Claim Exclusive Reservation // --- START CRITICAL SECTION --- shared_balance++; // Shared State Modification Block // ---- END CRITICAL SECTION ---- pthread_mutex_unlock(&bank_lock); // Exit Path: Release Reservation Line
