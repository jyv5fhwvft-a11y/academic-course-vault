Lecture 15: Classic Synchronization Problems & Deadlock Topologies Summary

1. Objective

Diagram resource dependency graphs to locate a circular wait condition and eliminate a deadlock trap by stripping out one of the four Coffman parameters.

2. Prerequisites

L14 (Race Conditions & Mutual Exclusion).

3 & 4. Pedagogical Analogies

Analogy 1 (Everyday Life): The Dining Philosophers Dilemma
Imagine five philosophers sitting around a circular dinner table with exactly five forks total placed between them. To eat a bowl of noodles, a philosopher must pick up both their left fork and their right fork. Suddenly, all five philosophers reach out and grab their left fork at the exact same millisecond (Hold and Wait). Now, everyone holds one single fork, and nobody can grab their second fork because they are polite and refuse to rip a fork away from their neighbor (No Preemption). Everyone sits frozen staring at their food forever. This freeze is a Deadlock. To break it, the manager breaks the loop condition (Circular Wait) by forcing just one philosopher to grab their right fork first instead, shattering the lock gridlock immediately.

Analogy 2 (Pure Technical): Recursive Bank Account Cross-Transfers
A deadlock matches a distributed system deadlock where Database Process A locks Row 1 and waits for Row 2, while Database Process B simultaneously locks Row 2 and blocks waiting for Row 1 to clear.

5. System Cohesion Matrix

• Feeds Into: Module 5 (File & Storage Management) — Concurrent read/write systems inside virtual file systems rely heavily on nested lock trees, which can crash the entire OS via kernel deadlocks if paths cross.
• Feeds Into: Module 6 (I/O Device Management) — Interrupt handler routines must be written to avoid locking resources held by preempted threads, preventing deadlocks inside Ring 0.

6. Core Breakdown

Synchronization primitives introduce complex resource interdependencies. A Deadlock is a state where a set of processes are permanently blocked because each process holds a resource and waits for another resource held by a different process in the same set.

A deadlock cannot occur unless all Four Coffman Conditions hold true simultaneously: Mutual Exclusion (unshareable locks), Hold-and-Wait (retaining locks while queuing for others), No Preemption (locks cannot be forcefully stolen), and Circular Wait (a closed loop chain of dependency). To prevent deadlocks, system designers must break at least one of these conditions (e.g., enforcing a strict global lock acquisition ordering hierarchy to prevent circular wait).

7. Lexicon / Terms

• Deadlock: A critical gridlock error state where multiple competing threads are paralyzed permanently while waiting for a closed loop of dependencies to clear.
• Semaphore: An advanced signaling synchronization variable that maintains an internal integer counter to manage thread traffic access caps.
• Coffman Conditions: The definitive mathematical requirements (Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait) that must all hold true for a deadlock to manifest.
• Circular Wait: An execution condition where a closed ring of processes exists such that each process waits for a resource held by the next process in the sequence loop.

8. Practical Example: Deterministic Deadlock Code Model

#include <pthread.h> #include <unistd.h> pthread_mutex_t lock_A = PTHREAD_MUTEX_INITIALIZER; pthread_mutex_t lock_B = PTHREAD_MUTEX_INITIALIZER; void* thread_one_routine(void* arg) { pthread_mutex_lock(&lock_A); // Claims Lock A sleep(1); // Forces a preemption window context switch pthread_mutex_lock(&lock_B); // Blocks waiting for Lock B held by Thread Two pthread_mutex_unlock(&lock_B); pthread_mutex_unlock(&lock_A); return NULL; } void* thread_two_routine(void* arg) { pthread_mutex_lock(&lock_B); // Claims Lock B sleep(1); // Forces switch pthread_mutex_lock(&lock_A); // Blocks waiting for Lock A held by Thread One pthread_mutex_unlock(&lock_A); pthread_mutex_unlock(&lock_B); return NULL; } // RESULT: Both threads hang indefinitely. The application freezes solid.

9. Interactive Classroom Activity

The Human Gridlock Loop: Arrange four student chairs in a tight square facing inward. Have four students sit down. Instruct them to reach out their right arm and firmly grab the left shoulder of the student sitting to their right (Hold and Wait). Now, instruct them that they cannot let go of a shoulder until their own left shoulder is released (No Preemption). Tell them to break free from the circle. Watch them realize they are deadlocked, and have them deduce which rule to drop to break the circle.
