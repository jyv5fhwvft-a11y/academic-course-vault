🎪 Ledgers vs Keys02 / 04

The Hotel Security Framework Analogy

Managing permission domains across large systems matches two competing tracking paradigms:

• Access Control List (ACL): A checklist clipped straight onto the door frame: "Who is allowed into Room 204?" It is resource-centric.
• Capability Token: An unforgeable electronic keycard handed to the guest context. The door doesn't care who you are; it opens instantly if your token fits. It is user-centric.

🔍 Matrix Slicing03 / 04

Decomposing the Security Matrix

The master Access Control Matrix maps subjects (rows) against objects (columns). Because matrices are massive and sparse, production kernels optimize them:

• ACLs (Columns): Slice the grid vertically. The permission ledger is tied right onto the resource asset container (e.g., standard files).

• Capabilities (Rows): Slice the grid horizontally. Unforgeable tokens are distributed directly into process task blocks.

🛠️ Unix Permissions04 / 04

Bitwise UNIX Permissions Vector

Deconstructing standard 9-bit packed compact ACL implementations:

Target Vector Footprint: rwxr-xr-- 1. User (Owner) Bits: 'rwx' ➔ Full Read, Write, and Execute rights. 2. Group Bits: 'r-x' ➔ Group members can Read and Execute only. 3. Others Bits: 'r--' ➔ World callers can strictly read. Optimization: High-speed hardware bitmask checks protect core file nodes.
