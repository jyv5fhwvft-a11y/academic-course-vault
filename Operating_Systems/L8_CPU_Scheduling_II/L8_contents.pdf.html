Lecture 08: CPU Scheduling II Summary

1. Objective

Construct a priority starvation scenario, calculate priority aging fixes, and diagnose the architectural trap of Priority Inversion.

2. Prerequisites

L07 (CPU Scheduling I).

3 & 4. Pedagogical Analogies

Analogy 1 (Everyday Life): The Hospital Emergency Room Waiting Area
Imagine a hospital emergency room. A standard "first come first served" policy completely collapses the second an ambulance pulls up carrying someone bleeding out from an accident (Priority Scheduling). However, if the ER doctors only look at high-priority critical emergencies, a person sitting in the corner with a fractured arm might sit in the lobby waiting for three consecutive days without ever seeing a physician (Starvation). To solve this, the triage nurse uses Aging—every hour the patient sits in the waiting room, their priority level is boosted slightly until they eventually become the top-priority emergency.

Analogy 2 (Pure Technical): Audio Buffering vs. Background Indexing
Advanced scheduling behaves identically to a media system packet network, routing a critical 4K live audio sample array ahead of a background backup agent daemon, while dynamically penalizing the background agent's scheduling frequency bounds to prevent UI lockups.

5. System Cohesion Matrix

• Relies On: L07 (Scheduling Policies) — Builds upon basic queue structures by linking multiple preemptive tiers together.
• Feeds Into: Module 5 (Process Synchronization) — Directly interacts with locking mechanics, where priority configurations can cause a low-priority thread holding a lock to block a high-priority thread (Priority Inversion).

6. Core Breakdown

• Starvation Defect: Pure priority scheduling assigns every process a numeric value, always picking the task with the highest rating. This easily causes Starvation (low-priority jobs never execute).
• Multi-Level Feedback Queue (MLFQ): Structures multiple distinct ready lines, each with varying priority tiers and time quantums. New tasks enter the top-tier queue with a short quantum. If they consume their entire time slice without yielding, MLFQ downgrades them to a lower-tier line with a longer quantum.
• Dynamic Balance: This adaptation mechanism effectively separates quick, interactive, I/O-bound tasks from heavy, compute-bound background batch jobs without requiring manual parameter configuration adjustments.

7. Lexicon / Terms

• Starvation: A scheduling defect where a process remains indefinitely delayed inside the ready state because higher-priority tasks keep seizing control.
• Aging: A kernel mitigation technique that gradually elevates a process's scheduling priority the longer it sits starved inside the ready queue.
• Multi-Level Feedback Queue (MLFQ): An adaptive CPU scheduling architecture that shifts tasks dynamically between historical execution runtime rows.
• Priority Inversion: An operational trap where a low-priority thread holding a resource indirectly delays a high-priority thread due to an intermediate medium-priority thread preempting the resource holder.

8. Practical Example: The Mars Pathfinder Glitch Case Study

The Priority Inversion Scenario: High-priority task TH requires a shared lock held by low-priority task TL. Suddenly, a medium-priority task TM arrives that does not require the lock. TM preempts TL because its base priority rating is higher.

------------------------------------------------================= CRITICAL REASONING CORE: Unresolved, T_L cannot execute to complete its scope and release the lock, which indefinitely paralyzes the high-priority thread T_H from running. RESOLUTION SYSTEM: Priority Inheritance T_L temporarily inherits the priority level of T_H to rush out of the critical section and release the shared lock. ------------------------------------------------=================

9. Interactive Classroom Activity

The Mars Pathfinder Trap Roleplay: Appoint three students as TH (High Priority), TM (Medium Priority), and TL (Low Priority). Hand TL an item representing a locked resource (like a dry-erase marker). Run the execution simulation on the board to visually demonstrate to the class how TM can accidentally paralyze the system, and have students propose a solution before you name Priority Inheritance.
